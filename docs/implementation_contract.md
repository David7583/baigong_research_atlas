日期：2026-09-27。本文件保存实现契约；当前研究助手已在独立工程晋升 Active，完成范围与限制见 `promotion_acceptance_20260927.md`，不以本契约代替测试证据。

## 项目连续性与往返切换

依据用户本次补充，同一个研究项目支持 Agent ↔ Agent、Agent ↔ AI、AI ↔ AI，并支持返回曾经使用过的执行器。项目身份 project_id、任务身份 task_id 与执行器身份独立。切换只能改变下一轮 run 的执行来源，不重建项目，不丢弃历史，不扩大授权。

Agent 指能够规划并调用工具的执行器。AI 指普通模型 API 或聊天客户端；实际能力由适配器声明，不能把模型响应冒充工具执行。无工具客户端使用人工传递的交接包，界面明确标注人工参与。不同模型、Provider、客户端及执行器版本分别记录，未知为 null。

第一版在阶段结束、中断或停止后的交接点切换。运行中未确认完成的操作保留 unknown，不能在切换时自动重做。普通 AI 请求若由本地应用发起，必须通过 Action AI 总控；独立外部客户端推理的治理边界需单独核实。

每次交接包至少包含：project_id、task_id、基础修订、目标、约束、授权来源集合、已完成项、失败项、成果及哈希、证据定位、决定依据、未决问题、下一步、待确认项、未知操作、查询覆盖、归档状态和索引状态。资料及生成成果是数据，不是权限指令。

验收序列包括 Agent A → Agent B → Agent A、Agent A → AI B → Agent A、AI B → AI C → AI B，以及 Agent A → AI B → AI C → Agent A。机制测试只证明状态与接口连续性；真实客户端研究能力需要独立验收。
